# FS113 — Interactive Clickable Character Conversation Interface with Hugging Face Starter Options and Custom Input

## Purpose

Establish required product `{functionality}` for direct, bidirectional player-to-patron conversation within the Obelisco barroom stage. Specifically:
1. Every visible bar patron in the playfield is interactively selectable via pointer click or touch.
2. Selecting a patron opens a dedicated **Character Conversation Box** visually themed in strict parity with the 16-bit retro RPG dialogue box.
3. The conversation interface provides three distinct conversation initiation pathways:
   - Two (2) AI-generated contextual conversation starters dynamically produced by the Hugging Face LLM dialogue service using the target patron's authoritative personality prompt file.
   - One (1) interactive custom text input field allowing the player to author and send their own arbitrary message.
4. Sending an initiating message (whether by selecting an AI-generated starter or submitting custom typed text) dispatches the message along with the character's authoritative persona context to the Hugging Face LLM dialogue node, receiving an in-character response verbalized through the retro dialogue interface.

## Current Baseline & Observed `{errors}`

### Current Architecture Limitations
1. **One-Way / Non-Interactive Patron Speech**:
   - Patrons only display dialogue when triggered by system events (such as delivering a drink or initial order placement in FS109).
   - Patrons cannot be engaged in conversation by the player, remaining passive background sprites.
2. **Restricted Sprite Click Targets**:
   - In [`PatronLayer.tsx`](file:///Users/diesel/Desktop/bartending/Bartending/src/components/PatronLayer.tsx), clicking a seated patron is solely wired to trigger drink service actions (`onServeDrinkToSeat`). There is no mechanism to open a conversational exchange or communicate verbally.
3. **Passive Dialogue Box Only**:
   - The current [`RetroRpgDialogueBox.tsx`](file:///Users/diesel/Desktop/bartending/Bartending/src/components/RetroRpgDialogueBox.tsx) component is an output-only display overlay that renders animated typewriter text and advances on click. It possesses no controls for user input, selectable prompt choices, or response submission.
4. **Missing Conversational Starter Generation**:
   - While the backend dialogue service handles `order` and `rejection` prompts, there is no conversational entry point capable of prompting the LLM for persona-driven conversation starters or conversational replies to freeform user text.

## Desired `{functionality}`

### 1. Interactive Character Selection in Playfield
- **Clickable & Tappable Patron Targets**:
   - All active patron sprites rendered in the barroom stage must serve as interactive hit targets for mouse clicks and touch taps.
   - When the cursor hovers over a patron, the cursor style must visually indicate clickability (e.g., pointer cursor), and the patron must be distinctly targetable without interfering with bar surface or background hotspot interactions.
- **Activation Behavior**:
   - Clicking an active patron initiates the conversation sequence for that specific character (`characterId`), activating the Conversation Box for that patron's seat and identity.
   - If drink delivery is in progress (e.g., active drag-and-drop of a cocktail), drink delivery takes priority; otherwise, clicking opens the conversation interface.

### 2. Retro-Themed Conversation Box Presentation
- **Visual Parity with Retro Dialogue Box**:
   - The conversation box must adhere strictly to the established 16-bit retro RPG aesthetic:
     - Deep navy blue background (`#09133b`).
     - Distinctive double white borders with pixelated corner loops matching [`retro_rpg_dialogue_box.html`](file:///Users/diesel/Desktop/bartending/Bartending/retro_rpg_dialogue_box.html).
     - Silver beveled portrait frame displaying the active patron's portrait asset (`sit` or `talk` sprite).
     - Gold speaker header (`#f7ca18`) displaying the character's canonical display name.
     - Pixel-style typography consistent with the rest of the retro interface.
- **Containment & Responsive Positioning**:
   - The conversation box must render neatly inside the console / POV playfield bounds.
   - It must remain fully visible and operational across both desktop viewports and mobile devices without overflowing, clipping, or causing browser viewport drift.

### 3. LLM-Generated Conversation Starters
- **Two Dynamic In-Character Choices**:
   - Upon opening the conversation box for a selected patron, the system requests two (2) distinct conversation starters from the backend Hugging Face LLM service.
   - These starter options must be dynamically derived from the target character's authoritative persona prompt file (`personality.txt`), reflecting their unique background, speaking tone, and quirks.
   - The starter choices must be presented as clearly selectable buttons or list rows within the conversation interface.
- **Loading State & Telemetry**:
   - While the LLM starters are being generated, the conversation box must display an active retro-styled indicator (e.g., animated ellipsis or "CONNECTING...") within the option slots.
   - If the generation call fails, the interface must surface a fatal error state indicating the failure rather than falling back to static dummy options.

### 4. Player Custom Text Input
- **Interactive Message Composition**:
   - In addition to the two AI-generated starter choices, the conversation box must provide an interactive text input field allowing the player to author a custom message.
   - The input field must feature clear retro styling (dark background, contrasting border, legible pixel or monospaced font) and descriptive placeholder text (e.g., `"SAY SOMETHING..."`).
   - A dedicated submission action (e.g., pressing `Enter` or clicking an accompanying "SEND" button) must transmit the custom message.
- **Input Constraints & Mobile Protection**:
   - Maximum input length must be bounded (e.g., 140 characters) to prevent runaway payload sizes.
   - On touch/mobile devices, focusing the text input must not trigger unwanted viewport zoom or break the console screen framing.

### 5. Conversational Exchange & LLM Node Processing
- **Persona Context Injection**:
   - Upon selecting one of the two starters or submitting a custom message, the selected text is transmitted to the backend LLM dialogue node.
   - The backend service deterministically resolves the character's authoritative persona (`personality.txt` via [`resolveAuthoritativePersona`](file:///Users/diesel/Desktop/bartending/Bartending/src/data/characterDialogue.ts)) and constructs a conversational completion prompt requesting an in-character response.
- **In-Character Response Presentation**:
   - The patron's generated response must be returned and displayed in the conversation box using the classic typewriter animation effect (matching speed and punctuation pauses of the established retro dialogue box).
   - Once typing finishes, the retro bouncing prompt arrow appears, allowing the user to acknowledge and advance/close the conversation.

### 6. Dismissal and Bar State Resumption
- **Closing the Conversation Box**:
   - The conversation box can be dismissed at any time by:
     - Clicking an explicit retro "CLOSE" or "CANCEL" control.
     - Pressing the `Escape` key (or console 'B' button).
     - Clicking the prompt arrow after the character finishes speaking.
- **State Integrity**:
   - Closing the conversation box cleanly restores the normal barroom interactive state without affecting patron seat timers, departures, or active drink crafting orders.

## Edge Cases & Error Handling

1. **Missing or Invalid `HF_TOKEN`**:
   - If `HF_TOKEN` is unset or rejected by the Hugging Face API, the service must immediately raise an explicit error (`HF_TOKEN_MISSING` or authentication failure status).
   - Silent fallbacks to canned or mock dialogues are strictly prohibited.
2. **Missing Patron Persona File**:
   - If a character lacks an authoritative `personality.txt` file and has no database biography, the system must raise `PersonaNotFoundError` and present the failure state explicitly.
3. **Empty or Truncated LLM Generation**:
   - If the LLM returns an empty string or whitespace, the service must throw a `DIALOGUE_EMPTY_ERROR` rather than rendering a blank dialogue bubble.
4. **Patron Departure While Conversing**:
   - If a patron reaches their departure countdown while in an active conversation, their departure must be temporarily held until the conversation is closed, or the conversation must gracefully conclude before the sprite exits.
5. **Simultaneous Drink Serving and Click**:
   - If the player is actively dragging a drink or tool over a patron, the drop target handler takes precedence over the conversation click to ensure drink delivery is not blocked.

## Acceptance Criteria

| ID | Category | Requirement |
|:---|:---|:---|
| **AC1** | **Patron Clickability** | Every visible patron on screen responds to click/tap by opening the conversation interface for that character. |
| **AC2** | **Retro Box Aesthetic** | The conversation box exactly matches the visual theme of `retro_rpg_dialogue_box.html` (navy blue `#09133b`, double white border, corner loops, silver portrait, gold name). |
| **AC3** | **Dual LLM Starter Options** | Opening the conversation box presents two distinct, dynamically generated conversation starters conditioned on the patron's authoritative persona prompt file. |
| **AC4** | **Custom Text Input** | A text input field allows the player to type and submit a custom message to the patron within the retro interface. |
| **AC5** | **In-Character Response** | Selecting an option or sending a custom message invokes the Hugging Face LLM service and renders the patron's reply with typewriter animation. |
| **AC6** | **Fail-Fast Enforcement** | Missing tokens, missing prompt files, network timeouts, or invalid responses fail fast with explicit diagnostic error feedback. |
| **AC7** | **Clean Dismissal** | The conversation box can be closed via dismiss button, `Escape`, or advancing past finished dialogue, returning to the normal bar state seamlessly. |
